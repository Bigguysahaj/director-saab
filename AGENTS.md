# Feature workflow

Follow this for every feature, fix, or idea that turns into work — including when just asked to "build X".

1. **Issue first.** Open a GitHub issue before any code. Title: `ENG-xxx: <short title>` (next free number, zero-padded to 3). Body: a few lines — what and why, plus scope / out of scope. Keep each issue small and focused; split anything bigger. Never mention AI, Claude, or "generated by" in issues, PRs, or commits (no Co-Authored-By lines).
2. **Wait.** The owner reviews the issue. Don't start until they say go.
3. **Test plan, approved.** Judge whether the issue needs tests or evals; very basic changes may not. If it does, propose the tests that prove it's done (as a comment on the issue) and wait for the owner to approve them. If it doesn't, say so on the issue and why.
4. **Tests before code.** Write the approved tests/evals first and confirm they fail for the right reason.
5. **Build to green.** Implement until those tests pass. Report honestly if they don't.
6. **Focused PR.** One PR per issue, branch named `fix/<problem>` or `feat/<feature>`, PR title starts with the ticket ID, body links the issue (`Closes #n`).
7. **Stale tests.** If a test or eval no longer earns its place, ask the owner before removing it; remove only on approval.
